HandyManager Proxy Structure Overview
Version context: v9.2.2 series
Audience: New engineers onboarding to afproxy

Purpose
- main.ts is the HTTP router and auth wall.
- handlers/ contains action-level business logic.
- lib/ contains shared integrations and utilities.
- config.ts + db.ts provide environment and persistence primitives.

Top-Level Layout
- root: main.ts, config.ts, db.ts, deno.json, landing.html, readme.md
- lib/: shared APIs/utilities (AppFolio, auth, fetch/retry, rate limits, SMS)
- handlers/: feature-specific endpoint handlers
- tests/: smoke and regression checks

ROOT FILES

main.ts
- handler (default export): central request router, action dispatch, auth/rate-limit gate, GET/POST switches.
- Key internal helpers: jsonResp, extractFrontendToken, isFrontendAuthorized, readSettingsTable, upsertSettingTable.

config.ts
- reportsHeaders, dbHeaders: AppFolio header builders.
- Exported constants: API hosts, auth/env values, CORS headers, cache/storage limits, version constants.

db.ts
- ensureTables: schema bootstrap.
- rowsAsObjects: result normalization helper.
- Cache API: cacheGet, cacheSet, cacheInvalidate.
- Storage controls: getCacheSizeBytes, getWebhookSizeBytes, evictCacheIfNeeded, webhookCleanup.

Quick Mental Model For New Engineers
1) Request enters main.ts default handler.
2) Auth and rate limits are applied first.
3) Action is routed to one handler function.
4) Handler calls lib/ and db.ts helpers.
5) Standard JSON response (or raw Response for specific routes like CSV/HTML/passthrough).

Where To Start For Common Tasks
- Add a new endpoint: main.ts switch + new/updated handler export.
- Add AppFolio fetch logic: lib/appfolio.ts, then call from handler.
- Adjust auth/session behavior: handlers/deviceAuth.ts + main.ts auth gate.
- Tune cache behavior: db.ts cache functions + handlers/passthrough.ts cache endpoints.
